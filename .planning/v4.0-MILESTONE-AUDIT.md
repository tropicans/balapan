## 4. Cross-Phase Integration & E2E Flows

1. **Standalone REST & DB Layer Integration:**
   - Standalone import/export REST APIs execute transparently over either `postgres` or `sqlite` via the unified `db` interface.
   - Batch imports use ACID transactions (`db.transaction()`) to guarantee zero partial writes during file parsing.

2. **Scaling & Real-Time Synchronization Flow:**
   - Data changes via Cashier/Admin REST endpoints emit WebSocket `STATE_UPDATE` broadcasts.
   - Multi-container node deployments propagate broadcasts across instances using Redis Pub/Sub (`@socket.io/redis-adapter`).
   - If Redis is absent (e.g. offline venue setup), the system automatically falls back to in-memory Socket.IO pub/sub.

3. **Rate Limiting Protection:**
   - Auth endpoints (`/api/auth/*`) capped at 20 req/min; general API routes (`/api/participants/*`, `/api/winners/*`, `/api/bracket/*`) capped at 120 req/min with standard headers.

## 5. Technical Debt & Deferred Items

- **Phase 29:** Batch CSV import uses synchronous memory buffering; chunked streaming is recommended for file sizes > 10,000 rows.
- **Phase 30:** PostgreSQL connection string requires active PostgreSQL instance when `DB_DRIVER=postgres`; auto-fallback gracefully switches to SQLite WASM if PostgreSQL connection fails.
- **Phase 31:** Redis URL parameter `REDIS_URL` defaults to in-memory fallback when unconfigured for local offline venue operations.
