<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration code → SQLite file | DDL/backfill statements and the copied backup file are the only filesystem mutations in this plan |
| process env → migration runner | `ALLOW_DESTRUCTIVE_MIGRATION` decides whether destructive steps execute |
| DB path (`DB_PATH`) → backup path | Backup location is derived from the DB path, not from input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02 | Tampering | `server/backup.js` `createTimestampedBackup` | mitigate | Filename is generated from `timestampTag(new Date())` only; directory is `path.join(path.dirname(dbPath), 'backups')`. No user input, event name, or request data reaches the path. Test asserts the target matches `data/backups/tamiya-\d{8}-\d{6}\.sqlite` |
| T-11-03 | Tampering | `server/migrations.js` backfill UPDATEs | mitigate | All interpolated-looking values use `db.prepare(...).run(boundValue)`; the default event id is a fixed constant read from the DB, never concatenated |
| T-11-04 | Tampering / Elevation | `runMigrations` destructive steps | mitigate | Steps carry `destructive: true`; the runner skips and logs them unless `process.env.ALLOW_DESTRUCTIVE_MIGRATION === 'true'`; default false in `.env.example` and `docker-compose.yml` |
| T-11-05 | Denial of Service | migration backfill performance | mitigate | Backfill is a single set-based `UPDATE ... FROM ROW_NUMBER()` statement; no per-row loop and no per-row `save()` |
| T-11-06 | Information Disclosure | backup files under `data/backups/` | accept | Express serves static only from `client/dist`; `data/` is not mapped over HTTP. Directory is gitignored |
| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | This phase installs no package; no slopcheck checkpoint required (RESEARCH Package Legitimacy Audit: none new) |
</threat_model>
